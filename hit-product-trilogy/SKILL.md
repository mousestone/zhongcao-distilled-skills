# 爆款产品三法则 + 4 种产品机会来源 + 用户体验公式

## R — 原文 (Reading)

> "雷军说:'爆款来自全面的优秀,外加至少一方面杰出。'要做出爆款产品,通常要同时解决下面这三个问题:第一,要'好'得足够明显;第二,要做到全面优秀;第三,准确地取舍。"
>
> — 吕白,《种草》附录 FAQ 7

---

## I — 方法论骨架 (Interpretation)

这个方法论在解决"为什么不是所有好产品都能爆"这个反直觉问题。它由三块拼成:

**第一块 — 爆款三法则**(雷军):(1) **足够好** — 某一方面做到明显杰出,用户能感知到超出;不是 1.5x 优势,而是超过用户感知阈值的 10x。(2) **全面优秀** — 其他用户在意的地方不能有致命坑;一项杰出掩盖不了十处短板。(3) **准确取舍** — 为新体验主动牺牲某些老体验时,要判断"什么更重要";这是反"做加法"思维的。三个条件**同时满足**才可能爆,缺一个就停在 4.5 分。

**第二块 — 4 种产品机会来源**(f07 + p35 合并): (1) **新要素的发现** — 行业普遍没意识到的要素你先发现,这就是新体验;门槛最低,适合率先进入。(2) **对重要程度认识的刷新** — 行业在某些要素上做出错误取舍(例如把硅油=坏),你重新定义重要度。(3) **新技术** — 在已知体验上做大幅提升(基础研究突破、新材料)。 (4) **新模式** — 用新组合降低优质体验门槛(共享、订阅、开源)。

**第三块 — 用户体验公式**(f20): 用户体验 = 用户想要的 − 用户不想要的。两侧必须**同时**列全,而不是单边堆砌;取舍的依据是"用户对各项的在意程度"。

三块拼在一起的产品决策流程:**用公式列全两侧 → 用 4 种来源识别机会类型 → 用三法则判断是否同时满足 → 上市后按 p47"上市才是研发的开始"持续迭代**。

## A1 — 书中的应用 (Past Application)

### 案例 1: BeBeBus 太空舱智能安全座椅
- **问题**: 传统儿童安全座椅笨重、转向困难,家长单手抱娃操作极不便利;市面上大量 1000 元价位产品功能雷同。
- **方法论的使用**: 用"用户体验公式"列全两侧 — 用户想要的(安全感、操作便利、颜值);用户不想要的(繁琐步骤、沉重感、低端感)。在"减少一个动作"上做到杰出 = **足够好**(f19/f20 法则一)。其他维度(材质/检测/安全标准)**全面优秀**(法则二)。从 1000 元跃到 5000 元定价是为"智能转向"这个新体验主动牺牲价格段 = **准确取舍**(法则三)。
- **结论**: 把"减少一个动作"识别为新要素 = 4 种产品机会来源中的"新体验/新要素发现"。
- **结果**: 上市后成为品类爆款,定价上探至 5000 元档仍能持续复购。

### 案例 2: 阿芙 11 籽精华油(从 1000 SKU 到 100+ SKU 的取舍样本)
- **问题**: 阿芙早期 SKU 多达 1000+,团队 700 人,看似选择丰富实则每个单品都不突出,无法形成爆款。
- **方法论的使用**: 用"用户体验公式"重新盘点 — 用户最想要的是"以油养肤的有效性",最不想要的是"选择困难 + 噱头产品"。砍掉 900 个 SKU 聚焦 11 籽精华油 = **准确取舍**(为有效性这个新体验,牺牲了 SKU 多样的旧体验)。选种子而非玫瑰花瓣(出油率高 + 有效成分高) = 在已知要素"以油养肤"上找到**更好的解决方案**(4 种机会来源 #3 新技术/新要素组合)。单一爆品在有效性维度做到明显杰出 = **足够好**。
- **结论**: 砍 SKU 是反"做加法"的取舍,选种子是反"贵=好"的刷新。
- **结果**: 阿芙 11 籽精华油成为战略转型锚点,带动品牌完成从"流量套利"到"以油养肤专家"的重定位。

### 案例 3(补充): INTO YOU 唇泥 — 4 种产品机会来源中"新要素发现"的样本
- **问题**: 唇膏(油光)+ 唇釉(水润)覆盖不了"雾面氛围感"需求;用户在评论区反复反馈雾面口红"拔干"。
- **方法论的使用**: 捕捉到"氛围感妆容"趋势后,把它识别为**新要素** = 4 种来源 #1。发明"唇泥"作为继唇膏、唇釉后的第三大品类。雾面 + 不拔干 = 在"不拔干"这项做到用户感知阈值以上的杰出 = **足够好**;同时保留显色度与持妆力 = **全面优秀**。
- **结论**: 新要素发现 → 品类创新 → 爆款,验证了机会来源 #1 的杠杆最大。
- **结果**: 2022 年天猫双十一唇部单品 No.1。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **新品立项**: 从 0 到 1 设计一个产品,需要决定"做什么、不做什么、做到什么程度"。
2. **产品评审**: 一个候选方案被汇报时,要判断它是否同时满足三法则,哪一项没满足。
3. **迭代决策**: 现有产品停滞,要判断是补功能(足够好没做到)、修短板(全面优秀没做到),还是砍功能(准确取舍没做到)。
4. **爆款诊断**: 产品评测分不错(4.5/5)却始终不是爆款,要拆解哪个法则没满足。
5. **机会筛选**: 团队捕捉到一堆趋势/灵感,要识别属于哪种机会来源(避免把"跟风"误判为"新要素")。

### 语言信号 (用户的话里出现这些就应激活)

- "为什么不是爆款" / "为什么评测分高但卖不动"
- "新品怎么取舍" / "这个功能要不要加"
- "怎么找产品机会" / "这个趋势值不值得做"
- "上市后还要做什么" / "产品迭代方向是什么"
- "够好就能爆吗" / "足够好是什么标准"
- "用户真正想要什么" / "用户在乎什么"

### 与相邻 skill 的区分

- 与 `reverse-funnel-strategy`(反漏斗人群扩散策略)的区别: **本 skill 是产品层**(做什么功能、做到什么程度、砍什么); reverse-funnel-strategy 是**营销层**(先打透哪个人群、用什么 6 要素匹配)。一个解决"产品本身能不能爆",另一个解决"产品怎么被看见"。
- 与 `planting-champion-7steps`(种草推动者 7 步骤)的区别: 本 skill 是**方法论工具**(诊断 + 决策),后者是**个人行动框架**(从找原点到建制度)。一个解决"做什么对",另一个解决"如何推动做对的事"。
- 与 `excitation-state-capture`(激发态捕捉)的区别: 本 skill 关注**事前产品定义**,激发态捕捉关注**事中用户信号识别**;前者是研发阶段的取舍,后者是运营阶段的观察。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

### 1. 诊断机会来源(对应 4 种产品机会来源)
- **做什么**: 用下面 4 个标签给候选机会分类:
  - **新要素发现**(门槛最低、率先进入可拿红利) — 例: INTO YOU 唇泥捕捉"氛围感妆容"趋势
  - **重要程度刷新**(反行业错误排序) — 例: 阿芙砍 SKU 重新定义"以油养肤有效性"
  - **新技术**(已知体验的大幅提升) — 例: 新材料、新工艺
  - **新模式**(降低优质体验门槛) — 例: 订阅、共享、开源
- **完成标准**: 候选机会被明确归到 4 类之一,若归不进,说明是"自嗨"或"跟风"而非真机会。

🛑 **STOP**: 若机会分类结果是"跟随热门做同质化产品"(反例 ce13),立刻停止 — 这是过去时的机会,无法创造新体验。

🔴 **CHECKPOINT 1 — 机会来源是否为真?**
问用户/团队:"这个要素是用户还没被满足的需求,还是行业已经解决过的问题?"
- 若答"行业已解决过" → 跳到 E 步骤 4(可能不是机会,不应立项)
- 若答"用户有需求但被忽视" → 继续

### 2. 列全用户体验公式两侧(对应 f20 用户体验公式)
- **做什么**: 把候选产品按公式两侧列全:
  - **用户想要的**: 解决问题、情感诉求、审美需要(列出全部)
  - **用户不想要的**: 金钱、时间、操作、认知等成本(列出全部)
- **完成标准**: 每一侧至少 5 项,且每项都能被目标用户访谈/差评/评论区数据验证。

🔴 **CHECKPOINT 2 — 公式两侧是否都列全?**
最常见的失败模式是只列"用户想要的"那一侧,疯狂加功能,却不削减"用户不想要的"那一侧 — 这种产品必败(对应 B 段反例 ce03: 自嗨型产品决策)。
- 若"不想要的"侧空白 → 立即停下来做用户测试/盲测/差评分析
- 若两侧都有但不知取舍 → 进入 E 步骤 3

### 3. 设计取舍 — 应用三法则(对应 f19 爆款三法则)
- **做什么**: 对每个候选方案做三法则检查:
  - **足够好**: 哪个方面做到"明显杰出"?能否超过用户感知阈值(10x 而非 1.5x)?BeBeBus 用"减少一个动作"做突破点。
  - **全面优秀**: 其他用户在意的地方有无致命坑?一个 4.5 分产品通常这一项勉强及格,但其他维度大量失分。
  - **准确取舍**: 为了"足够好"那一项,准备牺牲什么?阿芙牺牲了 SKU 多样,BeBeBus 牺牲了价格段。这是反"做加法"的关键。
- **完成标准**: 三项同时有明确回答;若其中任何一项是"我们想兼顾但没答案",该方案不应立项。

🔴 **CHECKPOINT 3 — 三法则是否同时满足?**
- 若"足够好"说不清 → 产品没激发点,做出来也不会爆,停
- 若"全面优秀"明显失分 → 即使亮点再强也会被短板拖垮,先修短板
- 若"准确取舍"是"什么都不想砍" → 必败,这是最常见的自嗨产品(反例 ce03)

if-fail fallback(若三法则过不了):
- 一线修复: 把方案退回 E 步骤 1 重新识别机会类型(可能选错了机会来源)
- 仍失败兜底: 若三法则中只有"全面优秀"满足,放弃做爆款的预期,改打"稳定基本盘"+ 长尾运营
- 🛑 STOP 信号: 团队不能清楚说出"我们为 X 牺牲了 Y"时,不要立项

### 4. 上线后持续迭代(对应 p47 "产品上市才是研发的开始")
- **做什么**: 把上市当作起点而非终点:
  - 设定迭代节奏: 每 2-4 周一个版本,基于真实用户反馈
  - 差评按"是不是目标用户"分层(对应 p36 差评处理 4 动作) — 非目标用户的差评可以放弃,目标用户的关键问题必改
  - 内部标准必须领先于市场(对应用户价值公式),不接受"市场平均水准"
- **完成标准**: 上市 90 天内有 ≥ 3 个版本迭代,且每次迭代都能追溯到一个具体的用户反馈。

if-fail fallback(迭代停滞):
- 一线修复: 回到 E 步骤 2 重列公式两侧 — 大概率是某侧缺项被忽视
- 仍失败兜底: 若 3 个月迭代仍无突破,做一次"竞争对标盲测" — 用户对竞品和你产品的真实反馈往往揭示"重要程度"被刷新

### 5. 机会持续发现(对应 f07 新趋势发现 3 路径 + "存在即不合理")
- **做什么**: 把机会发现制度化:
  - 每周扫一次"行业没意识到的要素" — 重点关注生活方式变化、底层驱动迁移、新人群出现
  - 每季度做一次"重要程度刷新" — 行业在哪些要素上做了错误取舍?
  - 永不停下"还有改进空间"的判断(Babycare "存在即不合理" 信条)
- **完成标准**: 团队有持续捕捉机会的机制,不只是"老板灵光一现"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **已有产品的纯运营优化**(改落地页/客服话术/活动机制)— 这是营销和运营问题,不是产品决策,改用 reverse-funnel-strategy 或 excitation-state-capture。
- **营销内容设计**(种草笔记、达人脚本)— 这是内容生产,不是产品取舍,改用 reverse-funnel-strategy 的 6 要素匹配。
- **战略层选择**(要不要进新市场/要不要砍整个业务线)— 这是企业级决策,改用 planting-champion-7steps 或更宏观的战略框架。
- **技术架构选型** — 三法则关注用户感知,不关注技术合理性;技术选型应让位于工程师专业判断。

### 作者在书中警告的失败模式

- **反例 ce03 — 自嗨型产品决策**(老板/产品经理单方面拍板,缺乏用户盲测/路演就推向市场): 新品成功率不足 10%。**触发条件**: 团队内没有"用户体验公式"两侧的实证清单;**一线修复**: 强制要求至少 30 位目标用户盲测通过;**仍失败兜底**: 放弃该 SKU,转做内部小流量测试。
- **反例 ce13 — 跟随热门做同质化产品**: 看到竞品爆款就跟随,看似稳妥但失去创造新体验的可能,最终陷入同质化价格战。**触发条件**: 机会来源分类结果是"已知要素上更好解但竞品已做";**一线修复**: 退回到 4 种来源重新识别,聚焦"重要程度刷新"或"新要素发现";**仍失败兜底**: 若实在找不到新角度,**不做**,不要用"跟随"填补产品线。

### 作者的盲点 / 时代局限

- **三法则默认产品可以被"卓越"驱动,但忽略组织能力**: BeBeBus 和阿芙的成功背后都有极强的创始团队,如果团队本身不具备"做出杰出项"的能力,三法则变成空想。作者对"如何培养这种团队"着墨较少。
- **"足够好"阈值在书中未量化**: 书中只说"明显超出",没给出可操作的评估方法;实际执行需要团队有用户敏感度 + 测试预算支撑。
- **"准确取舍"偏艺术而非方法**: 牺牲什么、保留什么,最终是创始人/产品经理的判断,没有放之四海皆准的清单;在小决策上可能反复内耗。

### 容易混淆的邻近方法论

- **Geoffrey Moore《跨越鸿沟》"Whole Product"**: 强调提供完整解决方案,接近本框架的"全面优秀",但**不包含"足够好"**这一激发点概念。
- **Clayton Christensen "Jobs to be Done"**: 强调用户完成任务的场景,与"用户体验公式"同源,但**没有"取舍"作为独立原则**。
- **Kano 模型**: 区分必备/期望/兴奋属性,接近"全面优秀+足够好",但**不含"主动牺牲老体验"**这一激进做法。
- **精益创业 MVP**: 强调最小可行,但**不强调"足够好"的阈值**——MVP 哲学甚至鼓励"够用就好",与本框架方向相反。
