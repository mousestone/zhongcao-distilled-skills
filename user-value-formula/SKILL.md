# 用户价值公式 (user-value-formula)

## R — 原文 (Reading)

> "用户价值=生命周期价值+影响力价值+建议价值。……先有外部标准;再建立准确映射外部标准的内部标准;当内部标准渐渐领先并替代外部标准,企业就能基于内部标准快速迭代,做出更贴合用户需要的、超出用户预期的产品。"
>
> — 吕沛,《种草》第三部分 第3章 04节

---

## I — 方法论骨架 (Interpretation)

用户价值公式由两个相互嵌套的模块组成:**用户价值三要素**(衡量一个用户值多少) + **内部标准领先于市场**(决定企业能否独立判断用户价值)。

**三要素构成**:用户的全部价值 = 他自己未来还要继续购买的 LTV(基础层)+ 他发内容影响其他人的影响力价值(放大层)+ 他提建议帮企业改产品的建议价值(共建层)。只看 LTV,等于砍掉后两项,所有"赔钱但赢得人心"的动作都会在 ROI 评估中被砍掉;后两项恰好是种草生态的复利来源——用户从被动消费者变成价值共创者。

**为什么建议价值是"价值中心"而非"成本中心"**:传统算账里,用户调研/差评处理/社区运营都被记作"市场费用",ROI 算不出就会砍。本框架把它们算进用户价值公式的右项——建议价值高 = 用户主动帮你改进产品 = 节省你的研发试错成本 = 长期 LTV 的护城河。建议价值一旦被纳入资产负债表,社区/调研团队就不是支出而是投资。

**内部标准领先于市场**:只有内部评审标准既"映射外部"又"领先外部",企业才能基于内部标准快速迭代(参见皮克斯 8 次故事板迭代:外部观众测情绪+内部故事板领先——两步并行)。路径是 1) 起步用外部标准(NPS/好评率);2) 建立能映射外部标准的内部评审机制;3) 当内部标准领先于市场,就可基于内部标准快速迭代。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 皮克斯故事板 8 次迭代 (内部标准领先的典型)

- **问题**: 皮克斯一部电影要在上映前反复打磨剧本/分镜,如何在观众都没看过的情况下判断"这版够好"?
- **方法论的使用**: 每张故事板都邀请外部观众观看,观察他们的可观察行为(笑/泪/专注/走神)反推情绪反应——这是"用外部行为代理感受";同时皮克斯内部有 120 页剧本评审标准,这套标准既准确映射外部观众的反馈、又在多个维度上领先市场——内部评审者能基于这套标准在 8 次迭代里持续打磨出超出预期的产品,这就是"内部标准领先于市场"。
- **结论**: 内部标准不是"拍脑袋的品味",而是"经过外部校准、能先于市场识别好内容的判断系统"。
- **结果**: 8 次迭代后产出的电影几乎都是高质量作品;更重要的是迭代周期被内部标准压缩——不必等外部票房反馈就能确认方向正确。

### 案例 2: 阿芙精油 (建议价值驱动的战略转型)

- **问题**: 阿芙精油 2011-2012 靠淘宝流量红利崛起后,SKU 膨胀到 1000+、团队膨胀到 700 人,但绝大多数 SKU 既无复购也无口碑,处于"赔钱但赢不到人心"的局面;新 CEO 小乙接手时,按传统 KPI 应当砍 SKU、缩团队、降本。
- **方法论的使用**: 小乙没有按订单利润砍,而是按"用户价值三要素"重新评估——发现 1000 SKU 中只有约 100 个真正有复购(LTV 真实)、有用户自发分享(影响力价值真实)、有用户反馈推动迭代(建议价值真实)的产品;剩下 900 SKU 是"赔钱但没赢到人心"的双输。
- **结论**: 用户价值公式给出了"砍什么/留什么"的判别:三要素都健康的产品留,任一要素虚胖的砍。
- **结果**: 700 人/1000+ SKU 减到 200 人/100+ SKU,集中资源做"以油养肤"中的 11 籽精华油(单一爆款)。用户价值公式让"砍掉调研/砍掉社区"的反模式被识别为"砍未来 3 年护城河"——砍错 SKU 不砍错团队。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **团队价值评估场景**: 评估社区运营、用户调研、客服团队到底"值不值"——是成本中心还是价值中心?砍预算决策怎么下?
2. **产品迭代决策场景**: 产品已经按用户反馈改了 N 版,但数据没起色——是改得不够,还是内部评审标准就错了?
3. **NPS / 好评率失真诊断场景**: NPS 数字不错但用户增长停滞——是不是只追了 LTV 项,忽略了影响力价值和建议价值?
4. **跨部门预算分配场景**: "三笔预算并行"(产品线/营销/用户运营)如何让"赔钱但赢人心"的动作能立项?

### 语言信号 (用户的话里出现这些就应激活)

- "用户调研值得做吗 / 社区运营 ROI 算不出"
- "怎么算用户价值 / LTV 怎么度量"
- "内部评审怎么做 / 内部标准怎么建立"
- "为什么 NPS 失真 / 好评率涨了但营收没涨"
- "砍社区调研团队省钱吗 / 团队预算怎么砍"
- "产品迭代决策依据 / 用户反馈没用怎么办"

### 与相邻 skill 的区分

- 与 `triple-ledger-system`(算对账三账体系)的区别: 三账是**账目维度**——体验账/用户价值账/营销全链路账三层并行的财务结构;本 skill 是**用户维度**——把用户价值这个右项拆成 LTV+影响力+建议三要素。三账讲"算哪些账",本 skill 讲"用户这条账里到底算什么"。前者是工具层,本 skill 是标尺层。
- 与 `experience-management-loop`(双循环)的区别: 双循环讲"在效率循环外并行建立体验循环"——是组织运转机制;本 skill 讲"循环跑起来后,如何度量每个用户对组织的真实贡献"——是循环的评价标尺。
- 与 `ceae-planting-loop`(CEAE 四步)的区别: CEAE 讲"捕捉-理解-放大-激发"的工作流;本 skill 是工作流背后的"标尺"——回答"激发态用户到底值多少钱"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

### 步骤 1: 建立用户价值公式 (算出每个用户的真实价值)

- **动作**: 把现有用户数据按三要素拆开:
  - LTV: 用户从首次购买到流失期间的累计 GMV/复购次数
  - 影响力价值: 用户发布 UGC 次数 × 平均触达人数 × 转化系数
  - 建议价值: 用户反馈条数(评论/调研/客服)中被采纳并产生产品改进的条数 × 节省的研发成本
- **完成标准**: 能用一张表列出"过去 12 个月 Top 100 用户的 LTV/影响力/建议价值各自是多少",且三项都有量化指标(不是"影响力高"这种形容词)。

### 步骤 2: 建立内部评审机制 (让内部标准能映射并领先外部)

- **动作**: 招募/培养 5-10 名"用户型员工"(目标人群出身、文理兼修)组成内部评审委员会。流程:
  1) 用外部 NPS/好评率校准内部标准(每季度抽样对比)
  2) 把内部标准的"达标线"先定在外部标准线上
  3) 持续用"用户行为代理感受"(大笑/全神贯注/加购/搜索)做盲测
- **完成标准**: 内部评审委员会对新内容/新产品的过审率<50%(说明标准够严);过审产品的外部好评率/复购率明显高于未过审产品。

> 🔴 **CHECKPOINT**: 内部标准未建立之前,**严禁做大规模产品迭代**(只允许小范围 A/B 测试)。原因是:没有内部标准时,产品迭代只能靠用户反馈滞后驱动,大改=赌运气,失败成本极高。皮克斯 8 次迭代能反复改的前提是内部标准够准。

### 步骤 3: 让内部标准领先于市场 (从"映射外部"到"先于外部")

- **动作**: 当步骤 2 跑通后,逐步把内部标准的"达标线"提高到外部标准线之上:
  - 收集"内部觉得好但外部初期反响平平"的案例(超前判断的素材)
  - 定期复盘:内部标准领先的部分是否在 3-6 个月后被市场验证
  - 当验证命中率>60%时,内部标准已"领先"——可基于内部标准快速迭代,不再等外部数据
- **完成标准**: 内部评审→产品上市之间的时间被压缩到外部反馈周期的 1/3 以下(皮克斯式);新产品的内部过审版本,上市 3 个月后外部好评率/复购率显著高于历史均值。

> 🛑 **STOP** (错误路径停止信号): 当以下三种情况出现时,立即停止推进、回到步骤 1 重新校准——
> 1. 把建议价值当成本中心(把社区/调研/客服当作可砍的"市场费用"),而非价值中心
> 2. 只追 NPS 数字(只测第一项 LTV,不量化后两项),把 NPS 当 KPI 当唯一指标
> 3. 内部评审委员会全部由"非目标用户"组成(全员男性讨论女性产品、全员老人讨论 Z 世代需求)
>
> 任意一个 STOP 触发,意味着**内部标准已经失真**,继续迭代只会越改越偏。

> **if-fail fallback** (三段式失败兜底):
> - **触发条件**: 步骤 3 跑完一季后,内部评审版本上市后外部表现与未过审版本无显著差异(命中率<50%)。
> - **一线修复**: 暂停领先计划,把内部标准降回"映射外部"档位;花 1 季度重新做外部校准——让 100 个真实用户在不知情状态下使用新版本,记录可观察行为(大笑/全神贯注/搜索/加购),对比内部评审的预测准确率。
> - **仍失败兜底**: 若一线修复后命中率仍<50%,说明问题不在"标准"而在"人"——内部评审委员会的成员画像偏离了目标用户(全员不是目标人群,或缺乏"文理兼修"中"文"的那一面)。此时应解散委员会,从目标人群中重新招募,而不是继续调标准。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **单次营销活动 ROI 评估**: 一次促销、一次直播、一次广告投放——这些场景用 `(T+X) ROI` 和因果指标(本 skill 是长期用户价值评估,不是单次活动评估)。
- **纯品牌曝光价值评估**: 没购买的纯曝光、纯心智种草——用 `品牌力指数`,不用本 skill 把"建议价值=0"误判为低价值用户。
- **订单利润核算**: 一笔订单赚不赚钱、库存周转、定价——用 `订单利润账` 或 `三账体系`,本 skill 不替代这些。
- **预算总额分配**: "今年预算砍 30%"这类总额决策——用 `种草预算 4 阶段投资法`;本 skill 解决的是"砍哪个团队",不是"砍多少总额"。

### 作者在书中警告的失败模式

- **砍掉社区/调研团队看似省钱实则砍未来护城河** (verified.md Skill 9 V2 novel_question): 用户价值公式中,社区/调研团队产出的是"建议价值",用户自发分享产出的是"影响力价值"。砍掉这两个团队等于砍掉用户价值公式的 2/3——短期 LTV 不变,长期 LTV 必下降。**反例: ce29 把"理解用户"当不紧急任务被挤压**,紧急任务塞满员工时间,理解用户这种慢功夫被一直推迟,组织远离用户。
- **把"用户建议"当成本中心**(反例对应 ce17 唯 KPI 论): 阿芙早期 1000 SKU 中只有 100 个有真实复购+分享+反馈,其余 900 个是"赔钱但没赢到人心"的双输。如果只按订单利润砍,会一刀切砍掉调研团队,但调研团队的建议价值恰恰是帮助识别"哪 900 个该砍"的关键。
- **NPS 数字追到了但用户增长停滞**: 只测第一项 LTV,不量化后两项——是失真的标志。NPS 高+影响力价值 0 + 建议价值 0 = 用户满意但不愿分享/不愿反馈,属于"沉默满意"。
- **内部评审委员会全部由"非目标用户"组成**: 全员男性讨论女性产品、全员老人讨论 Z 世代需求——内部标准的输入就是错的,标准再严格也是错的标准。

### 作者的盲点 / 时代局限

- **三要素的量化系数缺乏成熟公式**: LTV 成熟,但"影响力价值"和"建议价值"的货币化换算在书中仍是定性描述(没有给出具体转化系数)。agent 在用本 skill 时,需自行决定如何把"一次分享"和"一条建议"折算成金额;过度量化会失真,不量化又无法比较。
- **建议价值高度依赖企业执行力**: 用户提了建议,企业能不能采纳、能不能转化为产品改进,是另一道关。公式把"被采纳的建议数 × 节省的研发成本"算入,但若企业内部流程跑不动,建议价值只是账面数字。
- **B2B/低频高客单场景未单独讨论**: 公式按 C2C 种草场景设计,LTV 计算周期可能很长(月均几十元的高客单耐用品 5 年才回本),影响力价值/建议价值的折算也未区分 B2B(机构客户的影响力有限)。

### 容易混淆的邻近方法论

- 与 **NPS (净推荐值)** 的区别: NPS 只测"你会不会推荐我",只覆盖 LTV 项(用户满意度和复购意愿);本 skill 三要素覆盖完整用户价值公式。NPS 高≠用户价值高。
- 与 **RFM 模型** 的区别: RFM 按 Recency/Frequency/Monetary 分用户价值层,只看交易数据;本 skill 三要素包含"影响力"和"建议"两个非交易维度。
- 与 **客户终身价值 CLV (Customer Lifetime Value)** 的区别: CLV ≈ 本 skill 的第一项 LTV;但 CLV 不包含影响力价值和建议价值。CLV 高但三要素不全 = 错估用户价值。
- 与 **北极星指标 NSM (North Star Metric)** 的区别: NSM 是单一关键指标(通常对应一个动作);本 skill 是评估公式,产出"三要素各自多少",不是单一数字。
- 与 **VOC (Voice of Customer)** 的区别: VOC 是用户反馈的收集流程,产出的是"原始建议";本 skill 把 VOC 收集到的建议算入"建议价值"——VOC 是输入,本 skill 是衡量 VOC 输出的尺子。
